## Performance & caching rules (never regress these)
- Container-level caches, keyed on the S3 object version (ETag, else LastModified): people.json (_people_cache, plus the by_id index), deals.json (_deals_cache), interest/companies (_data_cache via _versioned_s3_json), tenant/team index (_tenant_cache, rebuilt only on a new people.json version), Demand table (_cache), desk Raised (_raised_cache). A tab click never re-parses a snapshot whose version is unchanged.
- Version checks: _object_version HEADs a key at most once per S3_VERSION_TTL_SECONDS (60s) per container (_s3_version_cache); within a request, _cached_object_version reuses it.
- Slim people index: s3://full-pipeline-cache/syndicate-dash/people-slim.json = {"source_version", "built_at", "people"} with only PEOPLE_SLIM_FIELDS and PEOPLE_SLIM_CUSTOM_FIELDS (no "summary"). The request path reads ONLY this file, even when stale (never blocks a visitor on a rebuild); the full export is parsed on a request only when the slim file does not exist (first run, logged). People caches key on the slim file's version. Out-of-band Lambda events: {"task": "rebuild_slim"} (HEAD people.json; rebuild when its version != recorded source_version) and {"task": "warm"} (load slim/tenants/deals/interest/companies caches); neither renders a page. Adding a person field or custom_label read: add it to PEOPLE_SLIM_FIELDS / PEOPLE_SLIM_CUSTOM_FIELDS (tests enforce).
- Per request: shared models are memoized with _request_memo (_my_deals_model, _active_intros_model, _intro_buckets, _overview_model, get_firm_deals, get_firm_matched_buy_deals; _company_buy_stats has its own) — computed once, counted as calls_compute_<name>. Dynamo partition reads (get_intro_details, get_manual_intros) are memoized per GET request (_memo_partition_reads; POSTs never memoize) and fetched with get_manual_intros filtering by company in memory — never one Query per company.
- DynamoDB: never loop GetItem/Query per tenant or per row. Known keys -> _dynamo_batch_get (BatchGetItem, 100/call): desk Raised owner intro items, admin buyer-notes history. Many partitions -> _dynamo_parallel_map (32 threads via the Table's thread-safe meta.client): team partitions. Whole-desk aggregates (admin feature aggregate, desk Raised seller manual intros) = ONE shared Scan per request (_aggregate_scan_by_partition: AGGREGATE_SCAN_SEGMENTS=4 parallel segments, filter sk begins_with AGGREGATE_SCAN_PREFIXES feature#/manual-intro#, grouped by prefix+partition, memoized per GET incl. failure); each consumer falls back to per-partition Queries with a CloudWatch warning if the Scan fails. Adding another whole-desk aggregate: add its prefix to AGGREGATE_SCAN_PREFIXES, never a new per-tenant loop or a second Scan. Feature aggregate also cached FEATURE_AGG_TTL_SECONDS, dropped on any feature write. get_feature_requests is memoized per GET request by (partition, page); get_manual_intros by (tenant_email, company).
- _tenant_email_for_deal is O(1) (_seller_email_order map on the cached index) — never scan the tenant index per deal.
- Timing: one "TIMING ..." line per request with phases s3 / tenancy / model / dynamo / pipeline_api / render (+ calls_*). Admin key + &timing=1 appends a timing table to the page (_maybe_append_timing_table); ignored for everyone else. Benchmark harness: tests/perf_bench.py (synthetic 16k people, simulated S3/Dynamo latency; --profile for top functions).

Track record: won deals + "N deals listed · N won · N lost/obsolete since <date>" + collapsed "All closed deals (N)".
- Dates (fields confirmed from a live Pipeline deal): listed = created_at ("YYYY/MM/DD HH:MM:SS +ZZZZ", slashes normalized — _parse_pipeline_ts / _deal_listed_dt). Closed (archived deals only) = closed_time, else today − days_in_stage (_deal_closed_dt), labelled "Won <date>" for a Won stage else "Closed <date>" (_deal_closed_label). History line: "since <earliest created_at>".
